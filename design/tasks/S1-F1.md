# S1-F1: unsplit approach road may raise an extra clearance warning

Owner: dev · sprint S2 · non-blocking follow-up from the S1-BRIDGE review (PR #21, final
"VERDICT: APPROVED" comment) · recorded in [S1-REVIEW](../reviews/S1-REVIEW.md)

## Problem

When an OSM way tagged `bridge=yes` also contains its ramp/approach (the mapper did not split
the way at the abutment), the bridge profile treats the whole way as deck. The approach part is
then checked for under-deck clearance and can produce a clearance warning that is not real.
Output is still valid; it only adds noise to `report.json` warnings.

## Acceptance criteria

1. A bridge way whose first/last segments lie on terrain (deck-to-ground gap below the
   clearance threshold over a contiguous end run) treats that run as approach: no clearance
   warning, no under-probe there.
2. A real low bridge (gap below threshold over the middle span) still warns.
3. Split ways (current behaviour) are unchanged: same sample `package_id` unless the fixture
   gains a new row.

## Performance considerations

One pass over the already-sampled profile, O(samples); no new terrain queries.

## Expected tests

`tests/test_bridges.py`: unsplit-approach fixture (no warning), low-middle-span fixture (warns).
Each ≤ 5 s, no wall-clock asserts.

## Conflict domain

Hard: `core/bridges.py` (profile/clearance section), `tests/test_bridges.py`. Soft: fixture rows.
