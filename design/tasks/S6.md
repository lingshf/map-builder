## S6-PARITY: Munich CLI/Blender façade parity (#106)

Correctness. Checklist G10 has failed on Munich since v0.5.0 (D191); it was non-gating only for Sprint 5.

**Approach.** Diagnose first, then fix the smallest layer at fault. Reproduce with the four controls in
[#106](https://github.com/lingshf/map-builder/issues/106) and classify the difference as one of: corner
association, triangulation order, transforms (float rounding of positions), or the checker's hashing. The issue
already shows equal colour-only triangle multisets and unequal position multisets, so the checker or the position
rounding are the first suspects. Record the classification with evidence in the PR before changing code.

**Acceptance.**
1. The cause is named with evidence (the first differing triangle on both paths, before and after the fix).
2. If the checker was wrong: the accepted equivalence (for example a position tolerance, or a canonical corner
   rotation) is documented in `tools/style_check.py` and `docs/dev/tools.md`, and the existing swapped-corner
   negative tests still fail as intended. If an exporter was wrong: the fix is in the exporter.
3. Two parity matrices, both reported with the command lines and exit codes:
   * **Historical controls (#106).** The four Munich package pairs from the issue (v0.5.0 `6535f38` classic, D181
     `8ce3d28` classic, `a6dbe48` classic and stylized), rebuilt from the issue's pinned inputs. Checker fix: the
     PR-head checker exits 0 on all four unchanged artifacts. Exporter fix: the four still exit 1 (expected: the
     defect is in those artifacts), and the first differing node/primitive signature each reports matches the one
     recorded in #106. The triangle-level localization required by AC1 is new evidence captured from this pinned
     reproduction (#106 records no triangle).
   * **PR head.** `py tools\style_check.py parity` exits 0 on all four presets, both styles, built at the PR head.
4. A new negative test proves that a real colour swap between two corners of one façade is still detected.
5. No geometry change (issue scope). G0 passes on the full matrix; classic identity G3 passes strictly. If an
   exporter fix cannot keep classic GLB bytes identical, stop and escalate: merging needs a D-number exception that
   names the new classic baseline revision S6-REVIEW will use for G3.

**Performance.** Checker-only fix: no product timing check. Exporter fix: D91/D106 timing (3 alternating rounds,
offline frozen cache) on CLI Generate, Blender Generate and Blender Generate+Export against b04b769, each ≤ +5 %.
PR CI stays under 10 min; new tests run without Blender.

**Tests.** `tests/test_style_check.py` (equivalence and negative cases); Blender headless
`tests/blender/checks_parity.py` if an exporter changes.

**Conflict domain (hard).** `tools/style_check.py`, `tests/test_style_check.py`; if the exporter is at fault also
`map_builder/blender/export.py`, `map_builder/core/glb.py`, `tests/blender/checks_parity.py`; `docs/dev/tools.md`

## S6-DEMO-2COL: two-column, no-reference style sheets (candidate 5)

Enabler for S6-STYLE-TUNE and S6-REVIEW evidence. It replaces the D187 doc-only fallback
(`compose_two_column.py` in the checklist). This task delivers **all** the evidence tooling and region inputs that
STYLE-TUNE needs; STYLE-TUNE only runs it.

**Two stages.** (1) *Render* (needs `bpy`): the existing recipe run through Blender
(`C:\tools\blender-4.2.23-windows-x64\blender.exe -b --python tools\demo\style_render_recipe.py -- ...`) writes
`render-<camera>-before.png` and `render-<camera>-after.png`, unchanged. (2) *Compose and report* (no `bpy`, no
Pillow): a new entry point that reads those PNGs and writes the sheets and reports. It runs under plain
`py -3.12` from existing renders, and the render stage calls the same code in Blender's Python.

**Acceptance.**
1. The compose stage emits, per camera, a two-column before/after sheet with no `--reference`, and a **paired**
   ΔE2000 report: for every region, before mean RGB and ΔE, after mean RGB and ΔE, and the change, all from the same
   region rectangles on both images.
2. Region inputs are **preset-scoped**: one regions file per preset (`tools/demo/palette_regions_<preset>.json`;
   the existing Factoria file is kept and extended). The region key is `(camera, label)` within a preset's file;
   a camera may have several regions. The files implement exactly the [pinned region map](#pinned-region-map-for-ad)
   below: every listed `(camera, label)` exists, swatch rows carry the listed `target_hex`, contrast rows carry no
   target. Each rectangle lies wholly on its named surface in both the before and the after render (the geometry is
   identical, G0 and equal visual triangles), shown by a crop overlay in the PR.
3. The report also prints, for each pinned **contrast pair**, ΔE2000 between the two regions' mean colours in the
   same image, before and after.
4. PNG decode and encode use the standard library only (`zlib`, `struct`); an import guard test fails if PIL is
   imported.
5. On the Factoria regions and one pinned camera, the after-ΔE values equal those of the D187 fallback script
   (Pillow) to 0.01. The before values are checked the same way by running the fallback on the before image.
6. The three-column mode with `--reference` is unchanged (its existing tests pass unmodified).
7. The command lines for both stages are documented in `docs/dev/tools.md`, and the S5 checklist's fallback section
   links to them (Design applies the link); the fallback stays documented for the v0.6.0 record.

**Performance.** Tools only; no product code. The compose stage for the D140 camera set runs in ≤ 10 s on this host.
Unit tests run without Blender in under 5 s.

**Tests.** Recipe and compose tests (no Blender): sheet dimensions and column order, PNG round trip and signature,
paired-report fields, region-file uniqueness per preset, the no-Pillow guard.

**Conflict domain (hard).** `tools/demo/style_render_recipe.py`, `tools/demo/style_contact_sheet.py`,
`tools/demo/palette_regions_*.json`, their tests; `docs/dev/tools.md` (recipe section only; serialized after
S6-PARITY, see the roadmap order).

## S6-STYLE-TUNE: stylized contrast (candidate 3)

Looks good is the user's first priority (D137). Colour only.

**Scope.** The four observations from the v0.6.0 review, each a palette change in `map_builder/core/style.py`:
(a) Munich pale roofs and walls merge from drone height; (b) Pittsburgh water reads deeper than the S5-STYLE target;
(c) Bellevue-Factoria roads lack contrast against landcover; (d) grass is pale (N1).

**Acceptance.** All comparisons are against the b04b769 baseline cells (see the top of this page).
1. **G0** passes on the full matrix (4 presets × 2 paths × 2 styles). **G3** classic identity passes strictly.
2. **D139 budgets** for the stylized packages of all four presets, each against its own baseline: ≤ 8 material
   definitions; draw submissions ≤ baseline; visual triangles equal; render memory (vertex + index + texture bytes)
   ≤ baseline; 0 texture bytes; GLB size ≤ baseline; frame-time proxy (`tools/demo/style_frame_time_proxy.py`,
   D139 setup) ≤ baseline + 10 %.
3. Every row of the [pinned region map](#pinned-region-map-for-ad) passes its rule, shown by the paired report
   from S6-DEMO-2COL: swatch rows end closer to their target (after ΔE < before ΔE); contrast pairs reach
   after ΔE ≥ 15 and after > before. A row that cannot pass needs a D-number changing its target or rule (D203)
   before merge.
4. Two-column before/after sheets, stylized b04b769 vs stylized PR head, for these checklist cameras: (a) 4 Munich `overview`, 7 `roofs`, 8 `roofscape`;
   (b) 9 Pittsburgh `overview`, 13 `river-bend`; (c) 1 Factoria `overview`, 2 `factoria-interchange`;
   (d) 16 sample `top`, 10 Pittsburgh `dsm-ground`.
5. **G10** CLI/Blender parity (gating again after S6-PARITY) exits 0 on all presets, both styles. **Determinism:**
   two builds of the same preset, path and style at the PR head are byte-identical.

**Performance.** If only colour constants change, no D91 timing is needed. If any code path changes, D91/D106
timing (3 alternating rounds) on CLI Generate, Blender Generate and Blender Generate+Export against b04b769, each
≤ +5 %.

**Tests.** `tests/test_style_palette.py` pins the new values; `tests/test_style_defaults.py` unchanged.

**Dependencies.** S6-PARITY merged (so G10 gates), S6-DEMO-2COL merged (evidence).

**Conflict domain (hard).** `map_builder/core/style.py`, `tests/test_style_palette.py`. Soft: the sample slot
(`examples/synthetic_sample.mbmap`, D103) if the sample is stylized.
