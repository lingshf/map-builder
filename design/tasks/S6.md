## S6-PARITY: Munich CLI/Blender façade parity (#106)

Correctness. Checklist G10 has failed on Munich since v0.5.0 (D191); it was non-gating only for Sprint 5.

**Approach.** Diagnose first, then fix the smallest layer at fault. Reproduce with the four controls in
[#106](https://github.com/lingshf/map-builder/issues/106) and classify the difference as one of: corner
association, triangulation order, transforms (float rounding of positions), or the checker's hashing. The issue
already shows equal colour-only triangle multisets and unequal position multisets, so the checker or the position
rounding are the first suspects. Record the classification with evidence in the PR before changing code.

**Acceptance.**
1. The cause is named with evidence (the first differing triangle on both paths, before and after the fix).
2. If the checker was wrong: the accepted equivalence (for example a position tolerance, or a canonical corner
   rotation) is documented in `tools/style_check.py` and `docs/dev/tools.md`, and the existing swapped-corner
   negative tests still fail as intended. If an exporter was wrong: the fix is in the exporter, and G0 and G3 still
   pass on all presets.
3. `py tools\style_check.py parity` exits 0 on all four presets, both styles, at the PR head.
4. A new negative test proves that a real colour swap between two corners of one façade is still detected.
5. No geometry change (issue scope). G0 passes; if an exporter changed, classic identity (G3) passes or the PR shows
   why bytes change and that only GLB vertex order or float encoding changed.

**Performance.** Checker-only fix: no product timing check. Exporter fix: D91/D106 timing (3 alternating rounds) on
Blender Generate+Export, ≤ +5 %. PR CI stays under 10 min; new tests run without Blender.

**Tests.** `tests/test_style_check.py` (equivalence and negative cases); Blender headless
`tests/blender/checks_parity.py` if an exporter changes.

**Conflict domain (hard).** `tools/style_check.py`, `tests/test_style_check.py`; if the exporter is at fault also
`map_builder/blender/export.py`, `map_builder/core/glb.py`, `tests/blender/checks_parity.py`. Soft: `docs/dev/tools.md`.

Enabler for S6-STYLE-TUNE and S6-REVIEW evidence. It replaces the D187 doc-only fallback
(`compose_two_column.py` in the checklist).

to the recipe run. Unit tests run without Blender and in under 5 s.

signature, a no-Pillow import guard.

**Conflict domain (hard).** `tools/demo/style_render_recipe.py`, `tools/demo/style_contact_sheet.py`, their tests.

## S6-STYLE-TUNE: stylized contrast (candidate 3)

Looks good is the user's first priority (D137). Colour only.

**Scope.** The four observations from the v0.6.0 review, each a palette change in `map_builder/core/style.py`:
(a) Munich pale roofs and walls merge from drone height; (b) Pittsburgh water reads deeper than the S5-STYLE target;
(c) Bellevue-Factoria roads lack contrast against landcover; (d) grass is pale (N1).

**Acceptance.**
1. Colour constants and colour choice only: G0 passes on all presets and both paths; visual triangle counts and
   draw submissions equal the b04b769 stylized baseline; classic mode is byte-identical (G3).
2. For each of (a)–(d) the PR names the target in the S5-STYLE target table (or a proposed new swatch) and shows the
   ΔE2000 report before and after, per region, from S6-DEMO-2COL. Each item either moves closer to its target or
   the PR states why the target itself changes; a changed target needs a D-number.
3. Two-column before/after sheets for the checklist cameras that show (a)–(d): (a) 4 Munich `overview`, 7
   `roofs`, 8 `roofscape`; (b) 9 Pittsburgh `overview`, 13 `river-bend`; (c) 1 Factoria `overview`, 2
   `factoria-interchange`; (d) 16 sample `top`, 10 Pittsburgh `dsm-ground`.
4. CLI/Blender parity (G10, now gating after S6-PARITY) passes on all presets.
5. The D139 budgets are unchanged: ≤ 8 materials, 0 texture bytes in stylized mode, GLB ≤ baseline.

**Performance.** Constants only: no D91 timing needed. If any code path changes, D91/D106 timing on CLI Generate
and Blender Generate+Export, each ≤ +5 %.

**Tests.** `tests/test_style_palette.py` pins the new values; `tests/test_style_defaults.py` unchanged.

**Dependencies.** S6-PARITY merged (so G10 gates), S6-DEMO-2COL merged (evidence).

**Conflict domain (hard).** `map_builder/core/style.py`, `tests/test_style_palette.py`. Soft: the sample slot
(`examples/synthetic_sample.mbmap`, D103) if the sample is stylized.
