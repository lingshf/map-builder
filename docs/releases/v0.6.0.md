# v0.6.0 - stylized look

Maps now have a **stylized look by default**: a pastel palette sampled from
reference art, flat-shaded faces, clear blue water with a light shallow rim, and
no textures. The previous look is still there as **classic**. Only the
appearance changes: collision, heightfield, georeference and passage probes are
the same in both styles, so a drone flies the same map. The package schema stays
**2.1.0**.

Before/after images, viewer captures and the Blender panel:
[docs/demo/v0.6.0](../demo/v0.6.0/README.md).

## What is new

### Stylized is the default; classic is one switch away (#100, #103, #109)

| Where | Setting | Default |
|---|---|---|
| CLI | `--style stylized` / `--style classic` | `stylized` |
| Blender | **Content > Style**: Stylized / Classic | Stylized |

What the stylized look changes:

- **Terrain:** slopes of 35 degrees or more get lit and shadowed cliff colours,
  gentler slopes a soft brightness ramp, and the ground beyond a shore is sand.
- **Water:** open water is a clear sky blue. The `bank:` shore ramp next to it
  is a light shallow-water rim, then sand, so the edge reads as one continuous
  shore (#103, fixed for ponds in #109).
- **Trees:** three foliage tones by face direction and a fixed per-tree tint, so
  forests are not one flat green.
- **Buildings:** tagged `building:colour` and `roof:colour` keep their hue,
  pulled into the palette. Untagged buildings get a palette colour chosen from
  their id, so the same building gets the same colour on every build. Footpaths
  and tracks have their own pale colour.
- **No textures, smaller files.** Stylized ignores **Textures** and writes no
  normals (glTF then draws flat shading), with the same triangles. The visual
  GLB is 40–47 % smaller (table below). Each package uses 7 or 8 materials.

What stays the same in either style: `collision/map.mbcol`,
`collision/terrain.mbhf`, the georeference, passage probes and their results,
the blocked and dropped lists, and the triangle count of every object.
Only `visual/map.glb`, `NOTICES.txt`, `manifest.json` and `report.json` differ.

**Classic is the v0.5.0 look.** Pass `--style classic` (or pick Classic in
Blender) to keep it, with textures when Textures is on. A classic package
differs from v0.5.0 only by `generator.version` (so `package_id`) and by the
bank fix below.

### Fixed

- **Stylized ponds show a continuous shallow band** (#109). The light rim used
  to sit on land a few metres away from the water, as pale triangles beyond a
  sand ring. It is now the `bank:` ramp that touches the water. Colour only;
  classic packages are byte-identical.
- **Banks continue under elevated bridges** (#97). A shore-ramp
  strip was dropped whole when it touched a bridge, which left the water up to
  1.8 m above the bare ground beside the I-90 crossing on Bellevue-Factoria.
  It is now cut only under decks at grade (less than 2.5 m above the ramp).
  Bellevue-Factoria and Pittsburgh gain bank triangles and their `.mbhf` changes
  at those strip nodes. Munich and the sample are byte-identical.

### For developers

- **Work-count performance gate** (S5-PERF-GATE, #91): deterministic per-stage
  counters and a checker that flags regressions without wall-clock noise. Usage
  in [docs/dev/tools.md](../dev/tools.md) (#99).
- **Faster water stage** (S5-PERF-WATER, #105): indexed water masks cut the
  Pittsburgh `ring_edge_tests` count to 6.7 % of before. Every package is
  byte-identical. Adds the SwiftShader frame-time proxy for the three.js viewer.
- **Style tooling** (S5-STYLE-BASE, #85): `tools/style_check.py`, the
  `bellevue-factoria` preset, three style camera presets and the render recipe
  `tools/demo/style_render_recipe.py`.
- Tests: the default style is pinned on both paths (#107); Blender's
  terrain-edit export check targets `terrain:grid` by identity (S5-F4, #94); the
  floating audit no longer reports a roof edge as buried (S4-F8, #83).
- Docs: architecture and water/shore design (#90), developer tools and CI (#92).

## Results on real data

CLI builds from frozen offline data caches, `created_utc` pinned, at `850a772`.
The classic column is the classic baseline (the v0.5.0 look plus the bank fix
above), byte-identical to classic at `850a772`. These evidence builds predate the version bump, so they report
`generator.version` 0.5.0; the release-asset packages are rebuilt from the tag.

| Pittsburgh | 15,246,708 | 9,153,644 | 5,336,528 | 3,902,306 |
| Bellevue-Factoria | 25,746,980 | 15,316,096 | 9,178,387 | 7,005,552 |

The stylized Pittsburgh package validates `VALID: 0 error(s), 1 warning(s)`
(73 degenerate triangles, listed and kept as in v0.5.0), and the C#
reader reports `OK` with all 11 passage probes PASS.

The stylized default was checked on both paths (CLI and headless Blender) for
the sample, Munich, Pittsburgh and Bellevue-Factoria: collision, heightfield,
georeference and probes are unchanged, classic packages are byte-identical to
the baseline, only the GLB, `NOTICES.txt`, `manifest.json` and `report.json`
differ, and fresh stylized packages pass glTF-Validator, the Python validator,
the C# reader and the v0.3.0 readers. The full record, with the per-check
results and images, is issue #108.

## How to try it

1. Download `map_builder-0.6.0.zip` from this release's assets (not the
   automatic Source code archive). In Blender 4.2 LTS: **Edit > Preferences >
   Get Extensions > dropdown > Install from Disk...**, select the zip, and
   enable **Map Builder**.
2. Enable **Edit > Preferences > System > Network > Allow Online Access**.
3. Open **3D Viewport > Sidebar (N) > Map Builder**. Choose **Centre + size**,
   **40.437 / -80.016**, **1200 x 1000 m** (Pittsburgh). The panel with the
   new **Content > Style** control:
   [panel.png](../demo/v0.6.0/panel.png).
4. Click **Generate Map**: the scene is stylized. To compare, set
   **Content > Style** to **Classic** and generate again.
5. Set an output path, click **Export Map Package**, then **Validate Package**.

From the command line, in PowerShell from the v0.6.0 source root (Python 3.11
or newer). This builds the committed synthetic fixture offline in both styles;
it is invented data, not a real place. For real inputs, see
[docs/user/cli.md](../user/cli.md).

```powershell
$synthetic = @(
    '--osm', 'tests\fixtures\synthetic_area.osm', '--dem', 'tests\fixtures\synthetic_dem.asc',
    '--datum', 'SYNTHETIC', '--dem-license', 'SYNTHETIC test data (no licence required)',
    '--osm-license', 'SYNTHETIC test fixture (hand-written OSM-format XML, not OpenStreetMap data; no licence required)',
    '--lat', '47.0', '--lon', '8.0', '--width', '400', '--height', '300'
)
$stylized = Join-Path $env:TEMP 'synthetic-stylized.mbmap'
$classic = Join-Path $env:TEMP 'synthetic-classic.mbmap'
py -3.12 tools\mbmap_cli.py build @synthetic --out $stylized                  # stylized (default)
py -3.12 tools\mbmap_cli.py build @synthetic --style classic --out $classic   # v0.5.0 look
py -3.12 tools\mbmap_cli.py validate $stylized
py -3.12 tools\mbmap_cli.py validate $classic
```

Each command prints `VALID`; the synthetic map has a warning about two
degenerate collision triangles.

## Compatibility

- Extension **0.6.0**; package schema **2.1.0**, unchanged. `.mbcol` stays
  format 2 and the heightfield format 1. v0.3.0 and later readers accept
  v0.6.0 packages, stylized and classic.
- **The default look changed.** Scripts that relied on textured output must add
  `--style classic` (CLI) or select Classic (Blender). In stylized, the
  Textures setting has no effect. Maps generated before v0.6.0, and Python
  callers that build `PlanOptions` without a `style`, stay classic.
- **Blender export keeps the style chosen at Generate.** The style is
  recorded in the generated map, and **Export** reuses it; changing Style
  afterwards does not restyle the map (regenerate to switch). Textures at
  export matters only for a map generated as Classic.
- **package_id changes.** Packages report `generator.version` **0.6.0**, so the
  same inputs give a new `package_id`. The committed synthetic sample (built
  with `--style classic`) was regenerated; only its `generator.version`
  changed.
- Stylized GLBs have no `NORMAL` attribute. glTF viewers draw flat shading from
  the face winding; a consumer that requires normals must compute them.
- Stylized `report.json` has `options.style: "stylized"`; classic reports omit
  `options.style`, as before.

## Known limitations and follow-ups

- **Known issue: Munich CLI/Blender facade colours differ (#106).** The
  same Munich map built from the CLI and from Blender gets different facade
  colours. This predates v0.6.0: the parity check fails the same way on the
  classic baseline. Collision and flight data agree.
- **Stylized scenes read pale.** In Munich, pale roofs and walls merge; the
  Pittsburgh water is a deeper blue than the target; on Bellevue-Factoria the
  road network loses its dark contrast. Accepted for this release.
- **Decorations are not in this release.** S5-DECOR (draft #101) is deferred
  because it needs a Unity glTFast check that is not available yet.
- **Water-stage speed-up partly met its targets** (#105): `overlap_pairs`,
  `primitive_calls` and `overlap_edge_tests` stayed above their targets; output
  is unchanged.
- Carried over from v0.5.0: degenerate triangles are listed and kept, water
  tagging coverage, landcover staircase edges, and no water texture.
