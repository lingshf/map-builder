# v0.2.0 - fly under bridges and through tunnels (preview)

**Release candidate.** Map Builder now generates places a drone can fly
**under or through**: highway bridge decks with piers and parapets, road
tunnels with portals, and elevated building parts and building passages.
Each one has a passage probe that the validator and the C# reference reader
check against the exported collision. Package schema stays **2.0.0**.

## What is new

- **Bridges** (#21, #26): `highway=*` + `bridge=*` ways become editable deck
  solids. Deck height follows OSM `layer` (5 m clearance per layer, ramps of
  8 % or less). Piers are added where a deck stands more than 6 m above the
  ground (kept off roads beneath), and 1 m parapets on wide enough decks.
  Each deck gets a `deck` probe, and an `under` probe where clearance is at least 4 m.
- **Tunnels** (#22): `highway=*` + `tunnel=*` ways become flyable tubes. The
  terrain is cut only inside the bore, headwalls close each portal cutting,
  heightfield cells over the bore are NaN, and each tube has a `bore` probe.
- **Elevated parts and building passages** (#24): raised building parts get an
  `under` probe. `tunnel=building_passage` / `covered=yes` roads split their
  building and get a `passage` probe.
- **Honest probe reporting** (D21): after the whole scene is built, each probe
  is re-checked. Blocked probes are not exported; `report.json`
  `passage_probes_blocked` lists them with the blocking object.
- Pittsburgh demo preset and faster, deterministic tests (#23).

PERF-PROBE-INDEX (#25) was closed without merging; probe-check performance is
unchanged from the merged features.

## Real-data result: Pittsburgh (Fort Pitt Bridge and Tunnel)

The [v0.2.0 demo](https://github.com/lingshf/map-builder/blob/v0.2.0/docs/demo/v0.2.0/README.md)
shows before/after renders from the **same fixed v0.1.0 cameras**:

| | |
|---|---|
| Area | 40.437 N, 80.016 W, 1200 x 1000 m (D26), DSM On, seed 1 |
| Generated | 33 bridge decks, 20 piers on 3 bridges, 5 tunnel tubes, 6 headwalls; 3290 objects |
| Probes | 13 exported (11 bridge, 2 Fort Pitt Tunnel bores), all checked and PASS in both the strict Python validator and the C# reference reader; 29 blocked probes reported |
| Tunnel leak test | 4709 vertical rays around the 6 headwalls: 0 holes, 0 below ground |
| Build time, excluding download | median of 3: **19.0 s** (target 120 s or less) |
| CPU rendering | 8 renders + panel capture in 280 s (budget 30 min) |
| Release zip | installed into a clean Blender 4.2 profile; headless Blender checks: 0 failures |

The C# reader's probe accounting now matches the Python validator, so it checks
every probe within its budget, and validators no longer warn on headwall ids
(#27, D46).

## How to try it

1. Download `map_builder-0.2.0.zip` from this release's assets (not the
   automatic Source code archive). In Blender 4.2 LTS: **Edit > Preferences >
   Get Extensions > dropdown > Install from Disk...**, select the zip, and
   enable **Map Builder**.
2. Enable **Edit > Preferences > System > Network > Allow Online Access**.
3. Open **3D Viewport > Sidebar (N) > Map Builder**. Choose a small area with
   a highway bridge or road tunnel, for example centre **40.437 / -80.016**,
   **1200 x 1000 m** (Fort Pitt Bridge and Tunnel).
4. Click **Generate Map**. In **MapBuilder Report**, read `counts.bridges`,
   `counts.tunnels` and `passage_probes_blocked`.
5. Set an output path, click **Export Map Package**, then **Validate Package**.
6. Optionally check the package with the C# reference reader (.NET 8 SDK), from
   the v0.2.0 source root:

```powershell
dotnet run -c Release --project examples\csharp\MbmapReader -- C:\path\to\my_map.mbmap
```

No Blender? Build and validate the synthetic sample (bridge, tunnel, elevated
part and passage probes) with the CLI, from the v0.2.0 source root:

```powershell
py -3.12 tools\mbmap_cli.py build --osm tests\fixtures\synthetic_area.osm --dem tests\fixtures\synthetic_dem.asc --datum SYNTHETIC --dem-license "SYNTHETIC test data (no licence required)" --osm-license "SYNTHETIC test fixture (hand-written OSM-format XML, not OpenStreetMap data; no licence required)" --lat 47.0 --lon 8.0 --width 400 --height 300 --name synthetic_sample --created-utc 2026-01-01T00:00:00Z --out synthetic.mbmap; py -3.12 tools\mbmap_cli.py validate synthetic.mbmap
```

Expected: `VALID: 0 error(s), 1 warning(s)`; its 4 passage probes pass.
See the [bridges, tunnels and passages guide](https://github.com/lingshf/map-builder/blob/v0.2.0/docs/user/structures.md)
and the [fly-through check flow](https://github.com/lingshf/map-builder/blob/v0.2.0/docs/flows/flythrough.md).

## Compatibility and limits

- Extension **0.2.0**; package schema **2.0.0**, unchanged. v0.1.0 packages
  remain readable, but regenerate them to get bridges and tunnels.
- Highway structures only (D25). Railway bridges/tunnels (including
  funiculars), culverts, `man_made=bridge` outlines and `man_made=tunnel` are
  reported as unsupported.
- Decks are swept rectangles and piers are simple boxes at generated
  positions; there are no trusses, arches or cables. Ways are clipped to the area.
- Probes check a 1-1.5 m capsule against collision. They do not guarantee that
  a given aircraft fits. Edits are not re-probed: an edit that blocks a probe
  still exports a `VALID` package and replaces the previous one. The block is
  reported only as a `passage probe N is blocked` warning. Treat a blocked or
  unchecked probe warning as a stop, even when the package is `VALID`.
- The flight simulator's map loader remains consumer-side work; v0.1.0 limits
  on DSM correction, visuals and the provisional code licence still apply.
