# v0.3.0 - passages, roofs and the real-data v2 demo (preview)

**Release candidate.** This release closes v2. Elevated building parts,
building passages and tagged roofs are now shown on **real data** (Munich
Altstadt), next to the Pittsburgh bridges and tunnel. Both real-data maps are
attached as ready-made `.mbmap` packages. Package schema stays **2.0.0**.

## What is new

- **Second real-data area: Munich Altstadt** (#36, D49 outcome A). The
  `munich-altstadt` demo preset (48.1395 N, 11.5764 E, 400 x 400 m) has a real
  elevated building part, the Rid Passage building passage, a road tunnel and
  tagged OSM roofs, with fixed cameras.
- **Real-data map packages as release assets** (S2-F4):
  `munich-altstadt-0.3.0.mbmap` and `pittsburgh-0.3.0.mbmap`. Each has a GLB
  inside, triangle collision, a heightfield, passage probes and `NOTICES.txt`.
- **Fewer false bridge warnings** (#32): when a `bridge=yes` way is not split
  from its ramp, a road that joins that approach at grade (it shares an OSM
  node with the bridge way within 15 m along the deck, where the deck is still
  below clearance height) no longer gets a clearance warning. Roads that
  really pass under the deck, including the same road further along, are
  still measured and still warn.
- **Roof checks in headless Blender** (#34) and deterministic tests without
  wall-clock gates (#31, #35).
- **Correct generator version** (D50): packages now report
  `generator.version` 0.3.0, and a test keeps it equal to the add-on version.

## How to try it

1. Download `map_builder-0.3.0.zip` from this release's assets (not the
   automatic Source code archive). In Blender 4.2 LTS: **Edit > Preferences >
   Get Extensions > dropdown > Install from Disk...**, select the zip, and
   enable **Map Builder**.
2. Enable **Edit > Preferences > System > Network > Allow Online Access**.
3. Open **3D Viewport > Sidebar (N) > Map Builder**. Choose **Centre + size**,
   **48.1395 / 11.5764**, **400 x 400 m** (Munich Altstadt).
4. Click **Generate Map**. In **MapBuilder Report**, read
   `counts.building_passages`, `counts.tunnels` and `passage_probes_blocked`.
5. Set an output path, click **Export Map Package**, then **Validate Package**.

No Blender? Download `munich-altstadt-0.3.0.mbmap` or
`pittsburgh-0.3.0.mbmap` and check it from the v0.3.0 source root:

```powershell
py -3.12 tools\mbmap_cli.py validate munich-altstadt-0.3.0.mbmap
dotnet run -c Release --project examples\csharp\MbmapReader -- munich-altstadt-0.3.0.mbmap
```

Expected: `VALID: 0 error(s), 1 warning(s)` (degenerate triangles), and from
the C# reader `OK` with every passage probe PASS.

## Compatibility

- Extension **0.3.0**; package schema **2.0.0**, unchanged. v0.1.0 and
  v0.2.0 packages remain readable.
- **package_id changes from v0.3.0 on.** v0.1.0 and v0.2.0 packages report
  `generator.version` **0.1.0**, a known historical mislabel (D50). v0.3.0
  reports 0.3.0. Because the manifest changes, the same inputs now give a
  different `package_id`, even where the geometry is byte-identical to v0.2.0.
  The committed synthetic sample was regenerated.

## Known limitations and later items

- **Pittsburgh in headless Blender** fails validation on one downward-facing
  road triangle (`road object #1163`); the CLI build is `VALID`. This was
  already the case in v0.2.0. It is being fixed as **S2-F6** (D51) before the
  tag. *(RC note: pending.)*
- **S2-F5, roofs on real data:** of 67 tagged non-flat roofs in the Munich
  area, only **5** are built as tagged (4 gabled, 1 skillion). **62 fall
  back** (53 to flat, 9 to pyramidal), mostly gabled or hipped roofs on
  footprints that are not rectangular. `provenance.roof_shape` shows each
  fallback and its reason.
- **C# parity test race:** `tests/test_csharp_parity.py` runs `dotnet build`
  on the reference reader. If two test suites run in parallel, both builds
  write the same output files and one can fail with `CS2012`. Run the suites
  one at a time.
- **L5, local test timings:** some tests take several seconds on a local
  machine. They are measured only, with no gate.
- **Degenerate triangles (L1):** the validator warns about zero-area
  collision triangles: **76** in Pittsburgh and **59** in Munich. They do not
  affect validity.
- Unchanged from v0.2.0: highway structures only (D25); probes are 1-1.5 m
  capsule sanity checks; edits are not re-probed, so a blocked probe is a
  warning and the package is still `VALID`. Treat any blocked or unchecked
  probe warning as a stop. The simulator's map loader remains consumer-side
  work.
