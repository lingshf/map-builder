# v0.4.0 - real roofs and textures (preview)

**Release candidate.** This release closes sprint 3. Gabled and hipped roofs
are now built on many eligible L, T, U and other non-rectangular footprints,
and maps come with **textures** (facades, roofs, roads, terrain) in both the
CLI and Blender. Textures are optional: switching them off gives the
plain-colour look for the same v0.4.0 geometry. It does not bring back the
v0.3.0 roofs. Package schema is **2.1.0**, which is additive: v0.3.0 readers accept it.

## What is new

- **Gabled and hipped roofs on non-rectangular footprints** (#41, #48, #50).
  Eligible footprints (simple polygons with up to 64 vertices and no
  courtyard) can get a roof built from their straight skeleton. This is not
  every non-rectangular roof: a valid simple footprint can still fall back
  (see the numbers below). Hipped roofs slope on every
  edge, and gabled roofs get vertical gable walls on the ends that can be
  represented. In v0.3.0 these roofs fell back to flat or to a pyramid. When a
  gable end cannot be represented (the ridge would meet the gable edge outside
  it, or the end is a sliver), the roof is built **hipped** instead and
  `provenance.roof_shape` names the reason. `provenance.roof_construction`
  tells you how each roof was built.
- **Textures in the CLI and in Blender** (#42, #46, #49, #53). Facades, tiled
  and flat roofs, roads, terrain and structures get base-colour textures with
  world-scaled UVs, so a brick is the same size on every wall. They are **on by
  default**: CLI `--textures` / `--no-textures`, Blender **Content > Textures**.
  The palette colour is kept on average (the vertex colour is divided by the
  texture's mean brightness). In Blender, the Textures setting **at Export**
  decides the whole package (D86). When you export with Textures on, a mesh
  you added that uses a generated textured material but has no UV map gets
  world-XY fallback UVs and one warning per object. Nothing changes for meshes
  with plain materials, or when you export with Textures off.
- **Textures are free to ship.** The six textures are our own procedural work,
  dedicated to the public domain under **CC0 1.0**
  (`map_builder/assets/textures/LICENSE-textures.txt`, included in the
  extension zip). Each package lists its embedded images, their licence and
  SHA-256 in `manifest.json` `asset_notices` and in the "Assets" section of
  `NOTICES.txt`.
- **Collision is unaffected by textures.** `.mbcol` and the heightfield are
  byte-identical with textures on or off. The toggle changes the GLB
  (materials, UVs, images), `manifest.json` (`asset_notices`) and
  `NOTICES.txt` (the "Assets" section), so the `package_id` changes too.
- **Full type annotations** (#51, #52, #54): `map_builder` and `tools` pass
  `mypy` with `disallow_untyped_defs` (41 files). No behaviour change.
- **Blender and CLI agree** (#47): the Blender centre latitude/longitude is now
  stored at full precision and the default seed is 1, so the same area gives
  the same passage probes in both. Old `.blend` files keep their centre.

## Roofs: what to expect (honest numbers)

On the frozen Munich Altstadt snapshot, **29 of 67** tagged non-flat roofs are
built as tagged, against **1 of 67** for v0.3.0 measured with the same
geometric checker. This meets the agreed floor of 29 (D82) but **not the
original goal of 40 or more**.

| Tagged shape | Built as tagged, v0.4.0 | v0.3.0 (same checker) |
|---|---|---|
| gabled | 17 / 52 | 0 / 52 |
| hipped | 11 / 12 | 0 / 12 |
| skillion | 1 / 1 (unchanged: skillion was already built on any footprint) | 1 / 1 |
| pyramidal | 0 / 1 | 0 / 1 |
| quadruple_saltbox | 0 / 1 | 0 / 1 |
| **total** | **29 / 67** | **1 / 67** |

The other 38: 30 gabled roofs are built hipped with a named reason (21 ridge
outside the gable edge, 9 sliver ends); 4 build flat with a named reason
(courtyard, roof height 0, quadruple_saltbox, concave pyramidal); and
**4 near-rectangle gables are built analytically but fail the planarity check
with no named fallback reason** (S3-F1). The 5/67 published for v0.3.0 came
from an earlier, looser checker and is not comparable (D52, D70).

Half-hipped, gambrel, mansard, round and saltbox roofs remain rectangle-only.
`roof:direction` now follows OSM: it is the direction the slope faces, so
the builder aims for a gabled ridge perpendicular to it (D84). That is the
target, not a guarantee: on a skeleton gable the ridge bearing follows from
the footprint. If no emitted ridge is within 10° of perpendicular,
`provenance.roof_direction` reports `approximate: ridge NNN° vs tagged DDD°`.

Built from the RC with the frozen v0.3.0 data caches (offline), seed 1, DSM on.

| Python validator | `VALID`, 1 warning (59 degenerate triangles) | `VALID`, 1 warning (76 degenerate triangles) |

Three runs of each build were byte-identical. Textures embed 5 images

## How to try it

1. Download `map_builder-0.4.0.zip` from this release's assets (not the
   automatic Source code archive). In Blender 4.2 LTS: **Edit > Preferences >
   Get Extensions > dropdown > Install from Disk...**, select the zip, and
   enable **Map Builder**.
2. Enable **Edit > Preferences > System > Network > Allow Online Access**.
3. Open **3D Viewport > Sidebar (N) > Map Builder**. Choose **Centre + size**,
   **48.1395 / 11.5764**, **400 x 400 m** (Munich Altstadt). Leave
   **Content > Textures** on.
4. Click **Generate Map**, then look at the roofs and facades in Material
   Preview. Set an output path, click **Export Map Package**, then **Validate
   Package**.

No Blender? Download `munich-altstadt-0.4.0.mbmap` or `pittsburgh-0.4.0.mbmap`
and check it from the v0.4.0 source root:

```powershell
py -3.12 tools\mbmap_cli.py validate munich-altstadt-0.4.0.mbmap
dotnet run -c Release --project examples\csharp\MbmapReader -- munich-altstadt-0.4.0.mbmap
```

Expected: `VALID: 0 error(s), 1 warning(s)` (degenerate triangles), and from
the C# reader `OK` with every passage probe PASS.

## Compatibility

- Extension **0.4.0**; package schema **2.1.0**. The additions (UVs, embedded
  PNGs, `asset_notices`) are optional: the v0.3.0 validator and C# reader
  accept 2.1 packages and ignore them. `.mbcol` stays format 2 and the
  heightfield format 1. Older packages remain readable.
- **package_id changes.** Packages report `generator.version` **0.4.0**, so the
  same inputs give a new `package_id` even where the geometry is unchanged. The
  committed synthetic sample was regenerated.
- A consumer that ignores textures can keep using the untextured path: build
  with `--no-textures`, or ignore the GLB images and UVs.

## Known limitations and follow-ups

- **Roofs:** 38 of the 67 tagged Munich roofs are not built as tagged (see
  above), including **4 with no named reason** (S3-F1).
- **Degenerate triangles:** the validator warns about zero-area collision
  triangles: **76** in Pittsburgh and **59** in Munich from the CLI (72 and 58 from Blender; S3-F12). They do not
  affect validity.
- **C# parity test race:** two test suites run in parallel can both build the
  reference reader and one fails with `CS2012`. Run them one at a time.
- **Texturing cost:** UV assignment is pure Python; the Pittsburgh scene-build
  stage is slower (S3-F4). The whole build stays well under target.
- Unchanged: highway structures only; probes are capsule sanity checks; edits
  are not re-probed, so a blocked probe is a warning and the package is still
  `VALID` (treat it as a stop); the simulator's map loader is consumer-side work.
