# v0.1.0 - editable-map baseline (preview)

Build editable small-area maps in Blender 4.2 LTS from OpenStreetMap features
and Copernicus GLO-30 elevation, then export GLB visuals and authoritative
collision in a validated `.mbmap` package.

## What is included

- Terrain, buildings with basic roofs and courtyards, draped roads, water and
  procedural vegetation as ordinary editable Blender objects.
- Final evaluated mesh export, including transforms, mirrors and modifiers:
  GLB visuals, matching collision, optional heightfield, georeference, integrity
  hashes, attribution and orientation probes.
- **DSM correction: Auto / On / Off.** Auto lowers ground under mapped buildings,
  trees, forests and bridge decks for Copernicus maps; it leaves local elevation
  unchanged. CLI overrides are `--dsm-correction` / `--no-dsm-correction`.
- Package schema **2.0.0**, Python validation, a synthetic sample, C# reference
  reader and a reusable demo/viewer kit.

## Install the published extension zip

1. Download [map_builder-0.1.0.zip](https://github.com/lingshf/map-builder/releases/download/v0.1.0/map_builder-0.1.0.zip)
   from this release's assets. Do **not** use the automatic Source code archive
   as the Blender installation zip.
2. In Blender 4.2 LTS, open **Edit > Preferences > Get Extensions > dropdown >
   Install from Disk...**, select the zip without unpacking it, and enable
   **Map Builder**.
3. Open **3D Viewport > Sidebar (N) > Map Builder**.
4. For online Copernicus / Overpass generation, first enable
   **Edit > Preferences > System > Network > Allow Online Access**.
   The offline local-file sample needs no network permission.

See the [versioned installation guide](https://github.com/lingshf/map-builder/blob/v0.1.0/docs/user/install.md)
and [actual Blender sidebar](https://github.com/lingshf/map-builder/blob/v0.1.0/docs/demo/v0.1.0/panel.png).

## Try a map, edit and export

1. Obtain the [v0.1.0 source](https://github.com/lingshf/map-builder/tree/v0.1.0)
   for its offline fixtures. Follow the
   [sample settings](https://github.com/lingshf/map-builder/blob/v0.1.0/docs/user/generate.md):
   centre 47.0 / 8.0, 400 x 300 m, local synthetic DEM + OSM. This is invented
   data, not a real location; DSM Auto leaves the local DEM unchanged.
2. Click **Generate Map**, inspect **MapBuilder Report**, and edit a building.
   Set a fresh output path, click **Export Map Package**, then **Validate Package**.
3. Extract your validated `.mbmap` as a ZIP and use Blender's
   **File > Import > glTF 2.0** on `visual/map.glb` to inspect visuals.
   Keep the editable `.blend`: importing GLB does not restore add-on metadata.
4. From the v0.1.0 source root with Python 3.11+ (the command below uses 3.12),
   validate the bundled sample:

```powershell
py -3.12 tools\mbmap_cli.py validate examples\synthetic_sample.mbmap
```

Expected: `VALID`, zero errors; the sample's two zero-area triangles produce
one documented warning. Replace the sample path to validate your own package.

The [demo evidence and exact reproduction commands](https://github.com/lingshf/map-builder/blob/v0.1.0/docs/demo/v0.1.0/README.md)
cover synthetic editing, the real Pittsburgh area, same-camera DSM Off/On,
and generation of the three.js viewer bundle and summary.
See the [export guide](https://github.com/lingshf/map-builder/blob/v0.1.0/docs/user/export.md)
and [simulator handoff status](https://github.com/lingshf/map-builder/blob/v0.1.0/docs/user/simulator.md).

## Source-build fallback (instead of the release zip)

Only if you need to build the extension yourself, check out tag `v0.1.0` and
run from that source root in PowerShell, replacing the Blender executable path:

```powershell
$blender = "C:\path\to\blender.exe"
New-Item -ItemType Directory -Force dist | Out-Null
& $blender --command extension validate map_builder
& $blender --command extension build --source-dir map_builder --output-dir dist
```

Install the resulting `dist\map_builder-0.1.0.zip` using the same
**Install from Disk...** steps above.

## Compatibility and preview limits

Extension **0.1.0** and package schema **2.0.0** are independent versions.
Schema 1.x maps must be regenerated. Format support for bridges, tunnels,
structures and passage probes does **not** mean generated flyable passages:
bridges/tunnels are omitted and reported unsupported in this baseline.
Elevated buildings are closed solids; no interiors, streaming, LOD or frame-rate
guarantee is included. Visuals are untextured, flat-shaded approximations.
The flight simulator's map loader and triangle-collision adapter remain
consumer-side work, not a delivered playable integration.

DSM correction is inferred, never raises terrain, smooths hidden relief and
does not correct features missing from OSM. Enabled online correction adds a
mask-only Overpass request, increasing cold-cache time. Mask-request failure,
budget limits, insufficient unmasked ground or non-convergence warn and keep
the original surface model. Required DEM/content failures still stop generation.
Inspect `terrain_correction` in the report and processing notes in NOTICES.
Raw source hashes and package schema stay unchanged.
