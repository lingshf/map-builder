# v0.1.0 - editable-map baseline (preview)

**Release candidate: not yet tagged or published.** DSM correction from
[#11](https://github.com/lingshf/map-builder/pull/11) is pending; the final
baseline must include it before release authorization. No generated flyable
bridges, tunnels, elevated passages or simulator map loader are claimed.

## What you can try

- Install a Blender 4.2 LTS extension and generate editable terrain, buildings,
  roads, water and vegetation from Copernicus / OSM or local files.
- Edit meshes and modifiers, then export final geometry as GLB visuals and
  matching authoritative collision in a validated `.mbmap`.
- Inspect schema 2.0 packages, attribution, georeference, optional heightfield and
  orientation probes with the CLI and C# reference reader.

## How to try it

1. After publication, download **map_builder-0.1.0.zip** from the release assets
   (not Source code.zip). Before publication,
   [build the extension zip from the candidate](../user/install.md).
2. In Blender **Edit > Preferences > Get Extensions > dropdown > Install from
   Disk...**, select that zip, enable it, then open
   **3D Viewport > Sidebar (N) > Map Builder**.
3. Obtain the same version's source checkout. Follow the
   [offline sample settings](../user/generate.md): centre 47.0 / 8.0, 400 x 300 m,
   local synthetic DEM + OSM. This requires no network. The fixtures are
   invented data, not a real location.
4. **Generate Map**, inspect **MapBuilder Report**, edit a building, choose a
   fresh output path and click **Export Map Package**, then **Validate Package**.
5. To view the `.glb`, extract your validated `.mbmap` as a ZIP and use Blender's
   **File > Import > glTF 2.0** on `visual/map.glb`.
   [Detailed export guide](../user/export.md).
6. To check the complete `.mbmap`, run the
   [CLI or C# reference reader](../user/simulator.md). Actual flight-simulator
   loading and triangle-collision integration remain consumer-side work.

The [three-example demo and images](../demo/v0.1.0/README.md) show generation,
editing and validated package inspection. Repository-relative links above work
when browsing the source; on GitHub use the
[candidate user guide](https://github.com/lingshf/map-builder/tree/lingshf-release-v0-1-0/docs/user)
until the release tag exists.

The installed sidebar panel registers successfully, but a **visual UI acceptance
check is still pending**: this environment cannot initialize graphical Blender's
WGL context. The supplied images are genuine CPU renders, not sidebar captures.

## Compatibility and limits

Extension version **0.1.0** and package schema **2.0.0** are different version
lines. The current reader rejects schema 1.x; regenerate older maps.
Schema 2.0 reserves structure classes and passage probes, but the baseline
generator still reports bridges and tunnels unsupported. Elevated buildings
are closed solids, not flyable interiors.

Visuals are flat-shaded, untextured procedural approximations. Online acquisition
is not covered by CI or the offline demo; there is no LOD, streaming or frame-rate
guarantee. GLO-30 is a surface model, not survey-grade ground truth.
The source licence is **provisionally GPL-3.0-or-later**, awaiting owner
confirmation; data licences are separate. Redistribute source attribution
(`NOTICES.txt`) with maps.

## Packaging

An authorized `v0.1.0` tag triggers the existing release workflow, which checks
the extension manifest version and publishes the extension zip as a GitHub
**pre-release**. These notes are read from `docs/releases/v0.1.0.md`.
No tag or GitHub Release is created by the documentation PR.
